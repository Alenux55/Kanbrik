# 019: Restore live Calendar drop-slot feedback

Status: Ready as a bounded Calendar correction specification on 2026-11-14; not implemented. The owner reports that task dragging used to highlight its destination slot and no longer does. Current source review confirms no live blank-slot preview in the inspected Calendar implementation; it does not establish when/how the earlier behavior changed. Respect the current task 014 correction/re-review gate and preserve all staged/in-progress work. This correction does not require task 017 custom tags to be implemented first and can be prioritized separately.

## Outcome and inputs

While dragging a project/task/subtask work card over Calendar, visibly highlight the time interval or existing block that would receive the drop. The preview and final drop must use the same actual targeting, eligibility and time interpretation. It is visual feedback, not another scheduling form or a saved block.

Read AGENTS.md, README, product/architecture, the coordinator handoff, reviewed Calendar/task 013 gesture/history behavior, and task 017's filter contract if integrated. Inspect `src/components/calendar.tsx`, `src/lib/calendar-hit.ts`, Calendar styles and real pointer/overflow tests. Use the established Calendar/dnd-kit stack; no new library or schema/API change is expected.

## Source findings and scope

- `calendarDropTarget()` currently resolves rendered foreground events or snapped blank time at `onDragEnd`. Pointer tracking only updates a ref, so no blank-slot candidate is rendered during movement. Existing `BlockTarget` dnd-kit `isOver` feedback applies to block elements and is not a one-hour blank-time preview. Do not claim this proves a particular regression commit.
- Compute a live candidate using the same viewport-pointer hit testing and scheduling eligibility as the final drop. For blank time, preview the actual snapped one-hour interval in the source work's workspace; for an existing empty same-workspace block, highlight that block and preserve its interval. Pointer/scroll coordinates and column clipping must agree with the final handler, not use drag deltas that drift across scrolled panes.
- Preview must update during movement and relevant Calendar scrolling/resizing/view/range/filter changes. Keep it clipped/positioned within the Calendar's visible grid; if an interval extends outside the visible grid/day, show an honest clipped shape and explicit start/end/date rather than inventing a shorter scheduled duration.
- Occupied/foreign foreground events are not blank slots. An invalid destination receives no misleading valid highlight; a clear unavailable cue is acceptable. Preserve the existing explicit replacement rules and permitted overlap behavior. A task whose workspace is not currently eligible, inactive/trashed work or failed picker/session scope must not gain eligibility merely because a preview is drawn.
- Use the viewing user's zone and existing snap/DST rules. Show enough start/end/time-zone information to understand the proposed reservation. A gap/ambiguous time requiring explicit occurrence review must not appear as an unconditionally valid automatic save. Retain the current explicit Review action after release, with no automatic editor popup or silent DST choice.
- Use a distinct noninteractive preview layer (`pointer-events: none` or equivalent) that cannot intercept hit testing or change layout/scroll bounds. It must not become a real event, escape the account/session gate or recreate the previous infinitely expanding palette/document scrollbar. Color alone is insufficient; a time label and visible boundary help convey the target.
- Clear feedback on cancel/Escape, release, leaving the valid grid, unmount, account/access change, failed verification and invalidated range/filter/work context. It must never remain as a phantom saved reservation or reappear from an obsolete callback. Preserve deliberate click-to-edit and subsequent keyboard/touch activation after gesture cleanup.
- Hover/preview emits zero create/assignment/status writes. Release retains existing exactly-once/idempotent creation or assignment behavior, pending feedback and uncertainty/conflict recovery; no modal should mount during a normal direct drop. The final saved interval/assignment must match the displayed valid preview.
- Keep non-drag scheduling through New block/work selection, mobile scrolling/tap and the existing deliberate absence of touch-only drag requirements. Calendar project/tag/text filters from task 017 must not expose a hidden block as an assignment target or let the preview change the task/filter's workspace. Integrate whichever feature lands later against the other's reviewed contract.
