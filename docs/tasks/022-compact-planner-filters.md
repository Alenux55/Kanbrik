# 022: Compact basic and advanced filters across planner views

Status: Planned on 2026-11-15; implement after settings/tag work is integrated and reviewed in the default sequence. This task does not depend technically on bulk tag removal. No runtime changes or application checks were performed for this specification.

## Outcome and inputs

Replace tall lists of filter choices with one compact, consistent toolbar on Projects, Board and Calendar. Read AGENTS.md, README, product/architecture, current handoff, tasks 017–019 and the closed tag corrections. Inspect `projects-planner.tsx`, `board.tsx`, `calendar.tsx`, `task-labels.tsx`, Board/Calendar predicates, workspace preferences and account-bound draft/filter/session providers. Use the existing stack and canonical task model.

Confirmed direction: basic Project and Tags multi-select dropdowns, inline search, Advanced filters, and the same layout across the three views. The owner accepted retaining Hide completed in Advanced, normal placeholder behavior, and an optional Agenda alternative. Workspace workflows already permit several completed statuses: **Done and Won't do can both be completed**. Completion is metadata, never inferred from column names or a literal status ID.

## Shared basic toolbar

- Present Project dropdown, Tags dropdown, search box, Advanced button and compact Clear filters action near each page's heading. Replace Projects' separate Task tags block. Avoid a second expanded filter panel below the toolbar. Adapt to one/two contained rows on Android without document-wide overflow; the Calendar grid/Board column scroll regions remain separate.
- Dropdown triggers show a concise selection summary/count. Open a searchable checklist popover with multi-selection, selected-state feedback, clear-selection action and bounded internal scrolling. Distinguish identical names by workspace where several are in scope. Do not replace this with a tall permanently visible checkbox list or an awkward native multi-select requiring modifier keys.
- Use accessible buttons/checkboxes and a deliberate focus/dismissal model: keyboard opening, selection, Escape, return focus, touch targets, readable names and visible focus. Do not add a drag sensor to filter controls. Portals must remain inside the session gate and respect an open editor/advanced dialog.
- Search has a real accessible label and a gray placeholder, not a separate tall label section. Placeholder disappears when typing, rather than immediately on focus. Existing text persists until changed/cleared. Recommended basic selections/search apply immediately to displayed results; opening or changing filters sends zero work/status/scheduling writes.
- Show active advanced-filter count/state and matching counts without repeating large explanatory paragraphs. Empty/incomplete results have concise messages and a clear recovery action. Filtering never hides retained unsaved-input recovery controls or makes a hidden task appear deleted.

## Meanings and advanced controls

- Preserve AND across filter categories, OR across selected projects, and explicit own-workspace Any/All tag semantics. Basic dropdowns list authorized choices relevant to the view's workspace scope. Existing archived associations remain filterable/labeled; names never substitute for IDs. Do not merge same-name tags or statuses across workspaces.
- **Projects:** continues to browse the sidebar creation workspace; no new cross-workspace Projects browser is implied. Project choices constrain projects/Standalone in that workspace. Search project/task/subtask titles, and apply task tag/creation/last-edited restrictions to canonical tasks. Retain project/parent ancestry for matching descendants without counting context as a task match; matching project titles must not bypass restrictions on child tasks. Empty projects remain visible when unfiltered; a project-only title match can appear without matching tasks when no task tag/date restriction requires one. Keep project/task counts distinguishable.
- **Board:** retain existing project/Standalone, title substring, task-created and task-last-edited meanings. Move workspace selection, date ranges, tag Any/All and **Hide completed** into Advanced. Default Hide completed is off and its control is absent from the basic toolbar. When enabled it hides tasks in every status whose workspace definition has `completed=true`, e.g. Done and Won't do; renaming a status changes neither completion nor the filter.
- **Calendar:** retain the broader existing text search over work titles/descriptions, explicit project/parent names and block labels. Use a suitable placeholder such as Search work and blocks; do not relabel it Title search while silently retaining broader behavior. Project/tag/text compose consistently across palette, grid, Agenda and drop eligibility. Empty/project-only blocks still cannot match task-tag restrictions. Workspace visibility and tag Any/All move into Advanced. Do not invent Calendar date-metadata filters in this task; its visible schedule range already has a separate meaning.
- Task-created/edited date ranges use current viewing-user-zone inclusive days, matching Board's existing half-open conversion and validation. A child and parent have independent metadata. Scheduling is not a task edit. Do not introduce a custom-status filter or other new field unless separately assigned.
- Advanced uses the established Apply/Cancel dialog behavior. Discarding that filter form does not discard task/comment/list/block/tag drafts. Workspace preference saves stay server-backed and visibly pending/failed; the remaining filters stay per-account view memory, as before. Basic filter edits and a cancelled Advanced proposal must not race and silently overwrite each other.
- Board/Calendar workspace selections remain independent. Projects follows its existing workspace selector. Task 023 adds Calendar's Follow creation workspace mode; support that control through the shared Advanced presentation once integrated. Filtering is never an authorization boundary or a record-ownership transfer.
- Clear filters resets project/tag/search/date/completion restrictions, retaining the current view's workspace scope/mode. Changing visible workspaces does not silently rewrite retained drafts or task tags. If stored filters refer only to choices outside the current scope, show concise zero-match/clear feedback rather than fetching hidden choices into the toolbar or automatically widening scope. Genuine revocation removes protected workspace state through existing guards.

## Hierarchy, ordering and compatibility

- Treat any active Project/tag/search/date restriction as a filtered Projects view. Preserve the task 018 guard against reordering an incomplete sibling list; matching parent/child context is not a complete sibling set. Restore ordering controls only when the full scope is loaded and restrictions are cleared.
- Keep existing account-bound filters across planner navigation. Define explicit conversion for the old Board/Projects/Calendar filter state rather than resetting unrelated work drafts. No cross-view filter mirroring or new cross-device persistence for text/tag/date filters is implied.
- Late picker/metadata responses cannot repopulate another workspace/account, reset selections or resume an obsolete drag. Distinguish picker failure, missing choices and actual workspace access loss. Keep current failed-save/revision protections and task 017 recovery fixes.
